## Анализ первопричины

**Сбой счётчика:** `ShiftService.close` закрывает смену и формирует отчёт, но ранее не сбрасывал `Tenant.dailyOrderNumber`. Сброс добавлен в ту же транзакцию.

**Неполная интеграция СКНО:** методы открытия и закрытия смены по-прежнему содержат только `[СКНО STUB]`. В репозитории найдены поля учётных данных СКНО, но не клиент, протокол или адаптер для вызова «Титан-Плюс». Поэтому полный внешний сценарий нельзя безопасно реализовать без спецификации API/SDK и согласованного ответа для Z-отчёта.

**Проверка нумерации:** тест BNP-413 дополнен созданием заказа через гостевой HTTP API после закрытия смены, чтобы проверить поведение следующего потребителя счётчика.
