## Root Cause Analysis
**Bug**: Изменение сотрудника из `/staff` не сохраняется через API, а деактивация не вызывает существующий endpoint.
**Root cause**: `StaffPage.save` отправляет обновление методом `PATCH` с camelCase-полем `fullName`, тогда как `StaffController` предоставляет `PUT /admin/staff/:id`, а `StaffService.update` принимает `full_name`. Запрос отклоняется, поскольку после разбора тела сервис не находит поддерживаемых полей; аналогично, `StaffPage.deactivate` вызывает `PATCH .../deactivate`, которого нет в контроллере (`DELETE /admin/staff/:id`).
**Impact**: Сценарий редактирования и следующей деактивации сотрудника завершается ошибкой при реальном API; текущий BNP-470 UI-тест скрывает несовпадение, имитируя несуществующие PATCH endpoints.
**Fix approach**: Привести запросы страницы к существующему контракту API и обновить регрессионный тест, чтобы он проверял HTTP-методы и формат тела, которые реально принимает контроллер.
