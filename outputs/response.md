# Доработка PR #192 — BNP-481

## Issues/Notes

- Текущая открытая блокирующая ветка ревью требует интеграцию открытия и закрытия смены с СКНО «Титан-Плюс» и подтверждённый Z-отчёт.
- В `ShiftService.open` и `ShiftService.close` по-прежнему стоят заглушки `[СКНО STUB]`. В API есть только сохранение `cashRegisterSerial` и `unp`; клиент, протокол, формат ответа/ошибок и SDK в репозитории и приложенном контексте отсутствуют.
- Нельзя корректно реализовать внешние вызовы и регрессионный тест без согласованного контракта. Придумывание формата запроса или трактовки Z-отчёта создало бы фиктивную интеграцию, не подтверждающую требования BNP-481. Поэтому блокер не устранён.
- Для продолжения необходимы спецификация/SDK СКНО, способ авторизации и тестовый стенд либо утверждённый контролируемый контракт успешных и ошибочных ответов.
- Приложенный контекст не содержит `merge_conflicts.md`, `ci_failures.md`, `ci_failures_full.log` и `pr_files.txt`; конфликтные файлы и CI-сбои не указаны.

## Approach

- Сверены PR diff, критерии BNP-481 и все локальные упоминания СКНО, «Титан» и `dailyOrderNumber` в API и admin-web. Обнаружены настройки реквизитов и заглушки, но интеграционного клиента нет.
- В этом раунде производственный код и тесты не менялись: доступных требований недостаточно, чтобы написать проверяемую интеграцию СКНО.
- Ветка содержит ранее добавленный сброс `dailyOrderNumber` и проверку выдачи следующего номера через гостевой API. Это не закрывает блокирующее требование СКНО.
