# Результат доработки PR #210 — BNP-157

## Issues/Notes

- **BLOCKING по спецификации остаётся:** во входных материалах нет официального контракта API/webhook Оплати™ и sandbox-реквизитов. Совместимость форматов интеграции с провайдером пока не подтверждена.
- Файлы `ci_failures.md` и `ci_failures_full.log` отсутствуют, поэтому статус CI GitHub из локального контекста определить нельзя.
- В `pr_discussions_raw.json` у замечаний 89–91 отсутствуют `threadId` и `rootCommentId`. Адресные ответы создать нельзя; `outputs/review_replies.json` содержит пустой список, идентификаторы не выдумывались.

## Approach

- Проверил BNP-518: импорт запускается через `OnboardingController.importMenu()`, состояние проверяется через публичный `importStatus()`; прямого вызова worker-обработчика нет.
- В BNP-519 удалил подмену приватного `queue.add`. Гостевой заказ проходит через `GuestSessionService.createGuestOrder()`, созданный Queue/Worker тестовый адаптер доставляет задание зарегистрированному processor, а результат проверяется на внешней границе POS-клиента.
- В BNP-520 постановка и обработка задания проверяются через гостевой сценарий `createGuestOrder()`. Проверяется успешный ответ гостю при сбое очереди или POS; тест больше не вызывает worker-методы напрямую и не проверяет внутренние вызовы Prisma.
- Производственный код не менял. Блокер по спецификации Оплати™ требует официальных данных провайдера.
