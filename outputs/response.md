# Результат повторной проверки BNP-157

## Issues/Notes

- Блокирующий вопрос по контракту Оплати™ остаётся открытым: в предоставленном контексте нет официальных URL, форматов API и webhook или sandbox-параметров. Ответы BNP-213/214 прямо требуют получить эти данные у владельца интеграции. Реальную совместимость запроса и webhook подтвердить нельзя; придумывать контракт небезопасно.
- Открытое замечание о раннем webhook остаётся: при отсутствии платежа с уже записанным `providerTransactionId` обработчик сейчас завершает задание успешно и не повторяет обработку. Не менял это поведение без теста, воспроизводящего гонку через существующую границу приложения.
- Замечание о дедупликации по транзакции уже исправлено в текущем PR: при наличии `eventId` используется его хэш, без него каждой доставке присваивается новый UUID. Проверки обоих сценариев есть в `oplati-webhook-job-id.spec.ts`.
- В `input/BNP-157/` отсутствуют `ci_failures.md` и `ci_failures_full.log`; CI-дефектов в контексте не приведено.

## Approach

- Сверил открытые review threads с текущей реализацией и ответами по связанным вопросам BNP-213/214/215.
- Не менял код интеграции: без официальной спецификации невозможно реализовать совместимый протокол, а для раннего webhook требуется сначала добавить регрессионный тест на публичной границе обработки.
- Оставил ссылки на все четыре открытые inline-обсуждения в `outputs/review_replies.json`; ответы отмечают исправленное замечание и явно фиксируют оставшиеся блокеры.
