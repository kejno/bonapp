# Результат повторной проверки PR #210

## Issues/Notes

- **BLOCKING остаётся:** официальный контракт Оплати™ не предоставлен. В коде используются предположительные поля запроса, ответа и webhook, поэтому совместимость с реальным API не подтверждена. В локальных материалах есть ответы BNP-213/214, которые прямо требуют получить спецификацию и sandbox-реквизиты у владельца интеграции. Без них безопасно завершить этот пункт нельзя.
- Риск раннего webhook исправлен в текущей ветке: необработанное событие приводит к ошибке BullMQ job и повторным попыткам. Проверка `payments.service.spec.ts` подтверждает, что несопоставленное событие не считается успешно обработанным.
- Секреты интеграций шифруются, TCP health check СКНО ограничен allowlist, а UI Оплати™ больше не предлагает неиспользуемый API-ключ; эти изменения уже присутствуют в текущем commit и в этом раунде не менялись.
- В `pr_discussions_raw.json` не осталось открытых inline-thread с `threadId` и `rootCommentId`: inline-комментарии помечены resolved, а новые общие re-review записи не содержат идентификаторов для threaded reply. Поэтому файл ответов оставлен пустым.
- CI-логи и `merge_conflicts.md` в `input/BNP-157/` отсутствуют.

## Approach

- Сверил повторно проверяемые замечания с кодом ветки и локальной историей PR.
- Не менял контракт Оплати™ на предположительный вариант: для реализации требуется официальная спецификация API/webhook и sandbox-реквизиты.
- Проверил миграции: обе новые миграции добавлены, ранее существующие не изменены. Поиск по `providerTransactionId` и условиям `provider: 'OPLATI'` выполнен в `apps/api/src` и `apps/api/prisma`; обращения bePaid используют отдельный провайдер.
