# Переработка PR #237

## Issues/Notes

- Исправлено блокирующее замечание из открытого треда: выбранные чаевые теперь передаются через контроллер в сервис и включаются в сумму карточного платежа bePaid.
- Для активного платежа повторный запрос с другой суммой чаевых отклоняется; после истечения платежа можно создать оплату с обновлённой суммой.
- Тело запроса проверяется: чаевые должны быть неотрицательным числом с точностью до копейки. Если тело не передано, используется `0` для совместимости с прежними вызовами.
- Отдельных файлов CI-ошибок во входных материалах нет. В `pr_discussions_raw.json` найден один открытый адресный тред; общий комментарий без идентификаторов нельзя адресовать как review reply.

## Approach

- Сначала добавлен тест, воспроизводящий нулевые чаевые в созданном карточном платеже; он падал до исправления.
- В контроллере добавлена проверка `tipsAmountByn`, а сервис сохраняет чаевые в записи платежа и формирует сумму шлюза как сумму заказа плюс чаевые.
- Регрессионные тесты проверяют передачу `4.75 BYN` и ожидаемые `1725` копеек шлюзу, а также отклонение некорректных сумм на API-границе.
- Проверены вызовы `createCardPayment` поиском по `apps/api/src`: существующие вызовы без четвёртого аргумента сохраняют прежнее поведение благодаря значению по умолчанию. Изменения схемы и миграции не требовались.
