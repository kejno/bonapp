# Результат повторной проверки BNP-157

## Issues/Notes

- Блокирующий вопрос по контракту Оплати™ остаётся открытым: в предоставленном контексте нет официальных URL, форматов API и webhook или sandbox-параметров. Ответы BNP-213/214 требуют получить эти данные у владельца интеграции. Совместимость запроса и webhook с реальным провайдером подтвердить нельзя.
- Открытое замечание о раннем webhook остаётся: если событие приходит до сохранения `providerTransactionId`, consumer не находит платёж и завершает задание без повторной обработки. Этот риск не исправлен.
- Замечание о дедупликации по ID транзакции исправлено в текущем PR: при наличии `eventId` используется его хэш, без него каждой доставке назначается UUID. Оба варианта покрыты `oplati-webhook-job-id.spec.ts`.
- В `input/BNP-157/` отсутствуют `ci_failures.md` и `ci_failures_full.log`; CI-дефектов в контексте не приведено.

## Approach

- Разрешил конфликты выходных файлов, сохранив отчёт BNP-157 и четыре адресных ответа по открытым review threads.
- Сверил замечания с текущими материалами PR и ответами по связанным вопросам BNP-213/214/215.
- В этом раунде исходный код не изменял: официальный контракт недоступен, а исправление потери раннего webhook требует отдельного регрессионного сценария и надёжного механизма повторной обработки.
