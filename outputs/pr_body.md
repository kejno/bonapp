## Результат доработки автоматизации — BNP-538

**Статус:** 🚫 Заблокировано требованиями, неустранимыми в рамках тестовой автоматизации
**Тест-кейс:** BNP-538 — повторная фискализация при сбое СКНО

## Что проверено

- BNP-538 выполняет задачу через настоящий BullMQ worker и временный Redis.
- Проверяются три обращения к мок-СКНО, реальные задержки 5 и 30 секунд, статус `FISCAL_FAILED`, отсутствие номера чека и запись ошибки.
- BNP-537 проверяет успешную обработку платежа и сохранение номера чека через обработчик worker.

## Результат

- Фокусные тесты пройдены: 2 набора, 2 теста.
- BNP-538 остаётся заблокированным: в API нет интеграции или тестового пути для обязательного Sentry alert.
- Критерий одновременно ограничивает число попыток тремя и задаёт три межпопыточные задержки (5/30/120 секунд). Требуется уточнить политику повторов.

## Запуск

```bash
npm run test -w apps/api -- BNP-537 BNP-538 --runInBand
```
