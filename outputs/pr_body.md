## Результат доработки автоматизации — BNP-538

**Статус:** 🚫 Заблокировано неустранёнными требованиями и отсутствующей продуктовой интеграцией
**Тест-кейс:** BNP-538 — повторная фискализация при сбое СКНО

## Что проверено

- BNP-538 запускает задачу через BullMQ worker с временным Redis.
- Проверены три обращения к мок-СКНО, реальные паузы 5 и 30 секунд, статус `FISCAL_FAILED`, незаполненный номер чека и запись ошибки в NestJS Logger.
- BNP-537 проверяет успешную фискализацию и сохранение номера чека.

## Результат

- Фокусные тесты пройдены: 2 набора, 2 теста.
- Открытое замечание об alert в Sentry не устранено: доступная реализация не содержит Sentry-интеграции или тестового пути, а область этой задачи разрешает менять только тестовый код.
- Требование ограничивает число попыток тремя, но перечисляет три межпопыточных задержки (5/30/120 секунд). Для трёх попыток возможны только две паузы; критерий требует уточнения.
- Ответы на открытые inline-треды не добавлены, поскольку в этом раунде соответствующие замечания не устранены.

## Запуск

```bash
npm run test -w apps/api -- BNP-537 BNP-538 --runInBand
```
