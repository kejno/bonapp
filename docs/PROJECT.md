# BonApp — платформа для заведений (рестораны, кафе, бары)

## Контекст

Учебный проект для отработки полного SDLC с использованием AI-инструментов.

## Идея

Multi-tenant SaaS-платформа: заведения регистрируются, настраивают своё меню
и принимают заказы через единую систему. Гость сканирует QR-код на столе,
открывает меню и делает заказ.

## Роли

- **Гость** — сканирует QR на столе, смотрит меню, оформляет заказ.
- **Персонал заведения** — обрабатывает заказы, обновляет статусы.
- **Владелец/админ заведения** — управляет меню, столами, персоналом своего
  заведения.
- **Супер-админ платформы** — управляет тенантами (заведениями), биллингом,
  модерацией.

## Стек

- **Backend**: NestJS, архитектура — DDD (bounded contexts по доменам:
  Tenant, Menu, Order, Table/QR, Identity).
- **Frontend**: React.
- Multi-tenant с первого дня (изоляция данных по tenant).

## MVP (этап 1)

- Регистрация заведений (self-service onboarding, мультитенантность).
- Управление меню (категории, позиции, цены, доступность).
- Генерация QR-кодов на столы.
- Гостевой флоу: скан QR → меню → заказ.
- Персонал: приём и обработка заказов (смена статусов).
- Оплата — офлайн (на кассе), без онлайн-эквайринга.

## Вне MVP (следующие этапы)

- Онлайн-оплата (интеграция платёжного шлюза).
- Биллинг для владельцев заведений (подписка на платформу).
- Аналитика/отчёты для заведений.
- Уведомления (push/SMS) гостю о статусе заказа.

## Открытые вопросы

- Стек для инфраструктуры/деплоя — не решено.
- База данных — не решено (кандидат: PostgreSQL, с учётом multi-tenant
  изоляции по схемам или tenant_id).
